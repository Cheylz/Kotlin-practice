# Заметки по Kotlin

## 1. Списки и массивы

- `Array`: фиксированный размер, `arrayOf(1, 2, 3)`.
- `List`: нельзя менять, `listOf(...)`. `MutableList`: можно добавлять и удалять, `mutableListOf(...)`.
- В Android почти всегда используют списки, а не массивы.

```kotlin
val numbers = listOf(1, 2, 3)
val result = mutableListOf<Int>()
result.add(4)
```

**Где я ошибался:** в `for (n in numbers)` переменная `n` уже сам элемент, поэтому `numbers[n]` писать не нужно.

## 2. Циклы и условия

- `for (n in numbers)`: по значениям.
- `for (i in numbers.indices)`: по индексам (тогда `numbers[i]`).
- `for ((i, n) in numbers.withIndex())`: и индекс, и значение.
- Диапазоны: `1..5` (5 включено), `1 until 5` (5 нет), `5 downTo 1`, `1..10 step 2`.
- Цепочка `if / else if / else`: срабатывает только первая подошедшая ветка, поэтому самое узкое условие проверяют первым (FizzBuzz: сначала «кратно и 3, и 5»).

## 3. `in` и `!in`

- `x in list`: есть ли элемент в коллекции (`true` или `false`).
- `x !in list`: элемента там нет.
- Это короткая запись для `list.contains(x)`.

```kotlin
if (number !in result) result.add(number)  // удаление дубликатов
```

## 4. Классы

- `class Book(val title: String, val year: Int)`: поля объявляются прямо в скобках.
- `val`: поле нельзя менять, `var`: можно.
- Если переменная не переназначается, пиши `val`.
- Обычный `class`: `==` сравнивает объекты («тот же самый?»), а `println` показывает `Book@123abc`.
- `data class`: `==` сравнивает содержимое полей, `println` выводит читаемый текст, есть `copy(year = 2000)`.
- `data class` нужен для классов, которые просто хранят данные.

## 5. Инкапсуляция

- `private set`: читать поле можно снаружи, менять только через методы класса.
- Всегда спрашивай себя: какие «неудобные» значения могут прийти (0, отрицательные числа)? Проверяй их в методах.

```kotlin
var balance: Int = balance
    private set
```

## 6. Лямбды, `filter` и `map`

- Лямбда: маленькая безымянная функция `{ it * 2 }`, где `it` это текущий элемент.
- `filter { ... }`: оставить подходящие элементы.
- `map { ... }`: преобразовать каждый элемент.
- Цепочка читается слева направо: `numbers.filter { it % 2 == 0 }.map { it * it }`.
- Если лямбда последний параметр функции, её можно вынести за скобки: `applyToAll(numbers) { it + 10 }`.
- Тип `(Int) -> Int`: функция, которая берёт Int и возвращает Int. `() -> Unit`: без параметров и без результата.

## 7. Null safety

- `String`: всегда есть значение. `String?`: может быть `null`.
- `?.`: обратиться, только если не `null` (иначе результат `null`).
- `?:`: запасное значение, если слева `null`.
- `filterNotNull()`: убрать `null` из списка.

```kotlin
println(name?.length ?: 0)
println("Привет, ${name ?: "гость"}!")
```

**Где я ошибался:** `?:` рядом с `+` читается неожиданно, лучше собирать строку шаблоном `"${...}"`.

## 8. Интерфейсы и наследование

- `interface`: контракт «ты умеешь это», без готового кода. Классов-родителей один, интерфейсов можно много.
- `open class`: «ты разновидность этого», потомки получают поля и код родителя.
- Без слова `open` класс и метод в Kotlin закрыты для наследования и переопределения.
- Как выбирать: есть общий код или данные, значит `open class`. Разные по природе классы должны уметь одно и то же, значит интерфейс.

## 9. `enum`, `sealed class` и `when`

- `enum class Direction { UP, DOWN }`: фиксированный набор значений.
- `sealed class`: ограниченный набор вариантов, и у каждого могут быть свои данные (состояния экрана: Loading, Success, Error).
- `when` проверяет все варианты, и компилятор сообщает, если один забыт.
- Для проверки типа варианта используется `is`.

**Где я ошибался:** `println{"текст"}` с фигурными скобками это лямбда, а не текст. Нужно `println("текст")`.

# Android и Jetpack Compose

## 10. Основы Compose

- `@Composable`-функция рисует кусочек интерфейса. Это обычная функция Kotlin, только она «рисует», а не возвращает значение.
- `@Preview`-функция нужна только для превью в студии, в приложение не попадает. Эмулятор запускает настоящее приложение, превью показывает то, что написано в `@Preview` (поэтому там может быть другой текст).
- `Scaffold` даёт отступы (`innerPadding`), чтобы контент не залезал под системные панели.
- Раскладка: `Column` (вертикально), `Row` (горизонтально), `Modifier.padding(16.dp)`, `fillMaxSize()`.
- `Modifier.weight(1f)` внутри `Row` или `Column`: «займи всё свободное место».
- Кнопка: `Button(onClick = { ... }) { Text("...") }`. Лямбда `onClick` и лямбда с содержимым это то же, что лямбда последним параметром.

## 11. Состояние (state)

- Состояние это данные, при изменении которых Compose сам перерисовывает экран.
- `var count by remember { mutableIntStateOf(0) }`: число. Для записи `by` нужны импорты `getValue` и `setValue`.
- `remember { mutableStateListOf(...) }`: изменяемый список, за которым следит Compose. Обычный `mutableListOf` Compose не отслеживает: элемент добавится в память, а экран не обновится.
- Без `remember` значение создаётся заново при каждой перерисовке и сбрасывается.
- Таблица, что где живёт:

| Где хранится | Перерисовка | Поворот экрана | Закрытие приложения |
|---|---|---|---|
| `remember` | да | нет | нет |
| `rememberSaveable` | да | да | нет |
| `ViewModel` | да | да | нет |
| База данных (Room, DataStore) | да | да | да |

- Мелкое состояние интерфейса (текст в поле): `rememberSaveable`. Данные приложения: `ViewModel`. Всё, что должно остаться на завтра: база данных.

## 12. Списки

- `LazyColumn { items(list) { item -> ... } }`: рисует только видимые строки.
- `itemsIndexed(list) { index, item -> ... }`: если нужен индекс.
- Строку списка выносим в отдельную `@Composable`-функцию (например, `BookItem`).
- `data class` хранит данные, `@Composable` показывает их.
- Изменить элемент списка: `list[index] = list[index].copy(done = !list[index].done)`.
- Удалять нужно безопасно: `removeLastOrNull()` не падает на пустом списке. Удаление по индексу хрупкое, в реальных приложениях у элемента есть `id`.

## 13. TextField

- `TextField(value = text, onValueChange = { text = it })`: поле само текст не хранит. Мы показываем ему значение и обновляем его, когда пользователь печатает (состояние живёт выше, state hoisting).
- Пустые значения проверяем: `if (title.isNotBlank())`, `title.trim()`.

## 14. ViewModel

- Во ViewModel: данные и логика (список, методы «добавить», «удалить», «переключить»). На экране: показ и вызов методов на нажатия.
- Приватный изменяемый список и публичный только для чтения:

```kotlin
private val _tasks = mutableStateListOf<Task>()
val tasks: List<Task> = _tasks
```

- На экране: `viewModel: TaskViewModel = viewModel()`.
- ViewModel переживает поворот (Android пересоздаёт Activity, но отдаёт ту же ViewModel), но не закрытие приложения.
- Порядок работы: сначала метод во ViewModel, потом кнопка, которая его вызывает. Одно маленькое изменение, запуск, коммит.

## 15. Как три вопроса помогают начать

1. Что приложение должно помнить? (данные, состояние)
2. Что пользователь может сделать? (события, каждое это метод ViewModel)
3. Что показываем на экране? (экран рисует состояние и вызывает методы)

## Где я ошибался

- `listOf(1..100)` это список из одного диапазона. Нужно `(1..100).map { ... }`.
- Студия подставила не тот импорт: `android.widget.Button` вместо `androidx.compose.material3.Button`, `Role.Companion.Button`, `CaseMap`, `VerticalAlignmentLine`. В Compose почти всё должно начинаться с `androidx.compose...`.
- `?:` рядом с `+` читается неожиданно, собирай строку шаблоном.
- Два списка в `setContent` рисуются друг поверх друга (`Scaffold` не раскладывает их по порядку).
- Тест поворота: нужно нажать иконку поворота в системной панели эмулятора, иначе приложение само не перевернётся.
- Изменения «не работают»: сначала остановить приложение и запустить заново (иногда на эмуляторе остаётся старая сборка).

## Если что-то не работает

1. Прочитать текст ошибки целиком (Build внизу студии, Logcat для падений приложения).
2. `Unresolved reference`: не хватает импорта или не прошла синхронизация. **File → Sync Project with Gradle Files**.
3. Не помогло: **File → Invalidate Caches → Invalidate and Restart**.
4. Выводить в лог: `println(...)`, смотреть во вкладке Logcat (поиск `System.out`).

## 16. Навигация (Navigation 3)

- Две библиотеки навигации: **Navigation 3** (новая, стабильная с ноября 2025) и **Navigation Compose** (старая, 2.x, много в существующих проектах). Я учу Navigation 3.
- Идея: **стек экранов это обычный список**. Открыть экран: `backStack.add(ключ)`. Назад: `backStack.removeLastOrNull()`.
- Каждый экран описывается **ключом** (`NavKey`):

```kotlin
@Serializable
data object TaskListKey : NavKey          // экран без данных

@Serializable
data class TaskDetailKey(val taskId: Int) : NavKey   // данные для экрана лежат в ключе
```

- `@Serializable` нужен, чтобы стек экранов сохранялся при повороте. Для этого подключаются плагин `kotlin-serialization` и библиотека `kotlinx-serialization-core`.
- `NavDisplay` показывает текущий экран, `entryProvider` говорит, что рисовать для каждого ключа:

```kotlin
val backStack = rememberNavBackStack(TaskListKey)
NavDisplay(
    backStack = backStack,
    onBack = { backStack.removeLastOrNull() },
    entryProvider = entryProvider {
        entry<TaskListKey> { TaskList(onTaskClick = { id -> backStack.add(TaskDetailKey(id)) }) }
        entry<TaskDetailKey> { key -> TaskDetail(taskId = key.taskId, onBack = { backStack.removeLastOrNull() }) }
    }
)
```

- Данные на другой экран передаю **через ключ** (лучше `id`, а не индекс или название).
- Оба экрана вызывают `viewModel()` внутри одной `MainActivity`, поэтому ViewModel у них **общая**.

## 17. Экран сообщает о событии через лямбду

- Экран не открывает другой экран сам. Он получает параметр-лямбду и просто вызывает её: `onTaskClick: (Int) -> Unit`, `onBack: () -> Unit`.
- Кто решает, что делать, тот и передаёт лямбду (здесь `App()` с `backStack`). Это тот же приём, что `action` в моей функции `applyToAll`.
- Если у функции появился параметр без значения по умолчанию, **все вызовы нужно обновить**, иначе ошибка `No value passed for parameter`.

## 18. Работа с `id` вместо индекса

- Каждой задаче свой номер: `private var nextId = 1`, при создании `Task(id = nextId++, ...)`.
- `find { it.id == id }` вернёт задачу или `null`, поэтому тип `Task?`. Компилятор заставляет обработать «задача не найдена».
- Переключить: найти позицию через `indexOfFirst { it.id == id }` (вернёт `-1`, если нет), проверить `!= -1`, заменить через `copy`.
- Удалить: `_task.removeAll { it.id == id }`. В лямбде `removeAll` условие проверяется **для каждого элемента**, поэтому нужно сравнивать `it`.
- `items(list, key = { it.id }) { task -> ... }`: ключ помогает списку не путать строки при удалении.
